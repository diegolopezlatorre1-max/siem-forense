PREPARAR EL PC (Windows)
------------------------

CREAR LAS MÁQUINAS VIRTUALES (VirtualBox)
-----------------------------------------
Red host-only 192.168.56.0/24 (el PC es la .1). La VM del SIEM es la .101 y Kali la .103.
[x] En VirtualBox: Archivo > Herramientas > Administrador de red host-only.
      Crear/confirmar una red host-only con:
        IPv4 del adaptador: 192.168.56.1 / 255.255.255.0
        Servidor DHCP: deshabilitado (usamos IPs fijas)
[x] VM Ubuntu Server (SIEM) - 192.168.56.101:
      - Descargar Ubuntu Server LTS (22.04 o 24.04) .iso
      - Crear VM: 2 vCPU, 4096 MB RAM, disco 25 GB
      - Red: Adaptador 1 = NAT (internet); Adaptador 2 = Host-only (la red de arriba)
      - Instalar; durante la instalación marcar "Install OpenSSH server"
      - Fijar IP estática en el adaptador host-only (NetworkManager).
        El host-only suele ser enp0s8 (el NAT, enp0s3, toma 10.0.2.15).
        Verificá con:  ip -br a
          sudo nmcli connection add type ethernet ifname enp0s8 con-name hostonly \
            ipv4.method manual ipv4.addresses 192.168.56.101/24
          sudo nmcli connection up hostonly
        Si dice que la interfaz está en uso:  sudo nmcli device disconnect enp0s8  y repetir el up.
        (Sin gateway ni DNS: la salida a internet la da el NAT.)
[x] En la VM Ubuntu, instalar Docker y el plugin compose:
          curl -fsSL https://get.docker.com | sudo sh
          sudo usermod -aG docker $USER   (reloguear después)
      Comprobar:  docker compose version
[x] VM Kali (atacante) - 192.168.56.103:
      - Descargar la imagen de Kali para VirtualBox (o la .iso e instalar)
      - Crear/importar VM: 2 vCPU, 4096 MB RAM
      - Red: Adaptador 1 = NAT; Adaptador 2 = Host-only (la misma red)
      - Fijar IP estática en el adaptador host-only (NetworkManager).
        En Kali el host-only suele ser eth1 (el NAT, eth0, toma 10.0.2.15).
          sudo nmcli connection add type ethernet ifname eth1 con-name hostonly \
            ipv4.method manual ipv4.addresses 192.168.56.103/24
          sudo nmcli connection up hostonly
        Si dice que la interfaz está en uso:  sudo nmcli device disconnect eth1  y repetir el up.
      - Comprobar que están hydra y rockyou:
          hydra -h
          ls /usr/share/wordlists/rockyou.txt   (si está .gz:  sudo gunzip /usr/share/wordlists/rockyou.txt.gz)
[x] Probar la red host-only entre las dos VMs:
      desde Kali:         ping 192.168.56.101
      desde la VM Ubuntu: ping 192.168.56.103

SESIÓN 15 - Base de la API
--------------------------
[ ] Comprobar que el PC llega a PostgreSQL de la VM (puerto 5432), p. ej. con DBeaver.
[ ] Redis solo escucha en 127.0.0.1 de la VM. Elegir una opción:
      a) correr la API y las pruebas e2e dentro de la VM, o
      b) en docker-compose.yml cambiar "127.0.0.1:6379:6379" por la IP host-only de la VM.
[ ] Añadir al .env de la VM (ver .env.example):
      POSTGRES_HOST=localhost
      POSTGRES_PORT=5432
      REDIS_HOST=localhost
      REDIS_PORT=6379
      PORT=3000
[ ] En la VM, instalar dependencias y comprobar:
      git pull && pnpm install
      pnpm lint && pnpm typecheck && pnpm test
[ ] Con docker compose arriba y las migraciones aplicadas (sesión 16), correr los e2e:
      pnpm --filter api test:e2e
